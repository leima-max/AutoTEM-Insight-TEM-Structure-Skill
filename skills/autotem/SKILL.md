# AutoTEM traditional analysis

The existing host is the main agent. Translate the user's question into supported domain tasks; do not rebuild chat or an internal general planner. This release provides traditional tools and three bounded domain profiles. DL, a unified frontend, native profile installation and interactive revisions are not implied by this Skill.

Prefer the host's configured AutoTEM MCP tools from [tool contracts](references/tool-contracts.md). If they are unavailable, use the installed project adapter's absolute interpreter and approved CLI/JSONL command. Avoid guessing `python` aliases. JSONL `stdio` is a separate bridge, not MCP. For a missing runtime, connector or permission, read [installation readiness](references/installation.md) and give one targeted setup action. Skill discovery alone does not prove a runnable backend. Read the relevant [data-quality](references/profiles/data-quality.yaml), [diffraction](references/profiles/diffraction.yaml) or [atomic-strain](references/profiles/atomic-strain.yaml) profile. Templates are in [recipes](references/recipes.md).

Optional [Codex native-agent templates](references/native-agents.md) are provided without activation. Verify native loading, tools and actual dispatch for the current host before using them; otherwise keep sequential fallback.

1. Discover `list_capabilities`; check operation availability and exact parameter schemas. Inspect the authorized file with `inspect_input`, explicitly selecting dataset/frame/channel when needed. Never execute a request-provided script/module/shell path.
2. Choose applicable branches. Data-quality runs first. Diffraction handles FFT/direct diffraction, peaks, g/d and constrained indexing/matching. Atomic-strain handles atom detection, raw refinement, distances, relative intensity and conditional GPA/atom strain. A request need not run every branch. Delegate only through host-native subagents actually available; otherwise use sequential calls with `execution_mode=sequential` and report that mode. Profile files are responsibility contracts, not proof of installed native agents.
3. Obtain required scientific inputs through the host conversation. Ask for missing pixel scale/unit, candidate structures, reliable non-collinear g vectors or raw-coordinate reference ROI. Use persisted annotated figures/peak tables to identify points. ROI for GPA is `[y0,y1,x0,x1]` in original pixels. Validate replies; do not invent calibration, measurements, reference regions or phase certainty. Inspect/status can return `needs_input`; retain its request and evidence rather than looping.
4. Save a plan with operation IDs/parameters/dependencies and explicit budgets, keeping `network_enabled=false` unless online lookup is authorized. Validate it before submission. Registered defaults are reproducible starting values, not verified scientific optima. Do not submit unavailable/DL/frontend operations as successful placeholders.
5. Submit and read `get_run_status`. Prefer asynchronous submission and bounded status checks; `--wait` is available for short local calls. For sequential profile packages, append only new steps to a completed run with `run_id` after validation; keep the same input/selection/budgets and use committed roles. Never reuse old step IDs or modify old parameters. Inspect execution, scientific and review states separately. Transport `ok=true` and process exit 0 do not mean scientific pass. A `needs_input`, blocking warning or missing required result must be explained, not renamed completed.
6. List/read committed artifacts, then export JSON/HTML and optional PDF evidence summary. Cite the actual run's images, coordinate tables, masks, parameters and provenance. Preserve raw and old outputs. Changes to old scientific inputs from later user replies create a new run with `parent_run_id` rather than overwriting an old result.

Uncalibrated inputs can produce pixel candidates/diagnostics; they cannot yield absolute nm/pm measurements or physical phase assignment. Refinement uses raw data; processed/denoised coordinates are candidates. HRTEM contrast is not automatically an atom-column identity. GPA/reference/valid-mask limitations, heuristic confidence, relative intensity and constrained phase hypotheses remain explicit. `not_evaluated` is not pass, and user approval cannot remove a scientific blocker.

For each GPA displacement, strain or rotation result, cite its own step's quality mask. Read arrays and compute summaries only where the mask is true. Masked pixels appear as null in tool previews and can be zero-filled in downloaded arrays. If the mask is unavailable, explain the limitation and withhold measurements for those fields.

Return a concise account of the question, actually executed operations, usable measurements, uncertainty/limits, needs-input or failed tasks, and links/IDs for the evidence. Do not claim frontend opening, native subagent support, actual host installation or general scientific accuracy without their own verification records.
